1. 연산코드와 오퍼랜드
    => 명령어는 연산코드와 오퍼랜드로 이루어져 있습니다.
    => 연산코드는 명령어가 수행할 연산 / 오퍼랜드는 연산에 사용할 데이터, 연산에 사용할 데이터가 저장된 위치
    => 연산코드는 연산자 / 오퍼랜드는 피연산자
    => 연산 코드가 담기는 영역을 연산 코드 필드 / 오퍼랜드가 담기는 영역을 오퍼랜드 필드

    => 어셈블리어도 이러한 연산 코드와 오퍼랜드로 이루어져 있습니다.
    => push rbp / mov DWORD PTR [pbp-4], 1


2. 오퍼랜드
    => 오퍼랜드 필드에는 연산에 사용할 데이터 그 자체보다 연산에 사용할 데이터가 저장된 위치가 담겨있습니다.
    => 이 떄문에 오퍼랜드 필드를 주소 필드라고도 합니다.
    => 오퍼랜드는 명령어 안에 하나도 없기도 하고, 여러 개이기도 합니다.
    => 오퍼랜드가 하나도 없는 명령어 -> 0-주소 명령어 / 하나 -> 1-주소 명령어 / 둘 -> 2-주소 명령어..


3. 연산 코드
    => 명령어가 수행할 연산입니다.
    => 크게 네 가지로 나눌 수 있습니다. (데이터 전송, 산술/논리 연산, 제어 흐름 변경, 입출력 제어)


4. 주소 지정 방식
    => 오퍼랜드에 주로 주소를 넣는 이유는 명령의 길이가 제한적이기 떄문입니다.
    => 주소를 넣으면 데이터를 직접 넣는 것보다 큰 데이터를 다룰 수 있습니다.
    => 연산의 대상이 되는 데이터가 저장된 위치를 유효 주소라고 합니다.
    => 오퍼랜드 필드에 데이터가 저장된 위치를 명시할 떄 연산에 사용할 데이터 위치를 찾는 방법을 주소 지정 방식이라고 합니다. -> 대표적으로 5가지 존재
    
    => 즉시 주소 방식 : 연산에 사용할 데이터를 오퍼랜드 필드에 직접 명시하는 방식입니다. / 표현할 데이터 크기가 작지만 가장 빠릅니다.
    => 직접 주소 지정 방식 : 오퍼랜드 필드에 유효 주소를 직접적으로 명시하는 방식입니다. / 유효 주소 길이를 판단해야 합니다.
    => 간접 주소 지정 방식 : 유효 주소의 주소를 오퍼랜드 필드에 명시하는 방식입니다. / 이 떄 유효 주소의 주소가 유효 주소보다 짧아야 의미가 있고 메모리 접근을 두 번 합니다.
    => 레지스터 주소 지정 방식 : 연산에 사용할 데이터는 레지스터에 존재하고 레지스터 번호를 오퍼랜드 필드에 명시하는 방식입니다. / CPU 내부 레지스터이기에 빠르지만 레지스터 크기를 고려해야 합니다.
    => 레지스터 간접 주소 지정 방식 : 연산에 사용할 데이터를 메모리에 저장하고 그 주소를 저장한 레지스터 번호를 오퍼랜드 필드에 명시하는 방식입니다.
