1. Base_64 인코딩 방식_1
    1-1. 문자의 ASCII 정수값을 2진수로 변환합니다. -> 값의 범위는 16진수 이내입니다.
    1-2. 2진수를 6bit씩 자릅니다.
    1-3. 6bit을 Base64 테이블의 문자표에서 찾아 문자로 바꿉니다.
    1-4. 마지막 데이터는 6bit로 떨어지지 않는다면 비워진 자리에는 패딩이 붙습니다.
        => 패딩은 ==입니다.


2. Base_64 인코딩 방식_2
    2-1. Base64 인코딩 방식은 ASCII 인코딩 방식으로 만든 문자만 가능한 것이 아닙니다.
    2-2. 한글 문서를 기준으로 Base64 변환
        1. 가 작성
        2. 가를 Unicode에서 어떤 코드 포인트로 표현할지 결정합니다. (문자 집합)
        3. UTF-8를 통해 그 코드 포인트를 어떤 바이트로 변환할지 결정합니다. (인코딩)
        4. 그 결과 EA B0 80 3바이트
        5. 그 바이트를 Base 64 인코딩을 합니다.
        6. 24비트를 6비트 씩 분리합니다. 111010 101011 000010 000000
        7. base table에 의해 변환됩니다. 6rCA


3. 이미지 파일은 바이너리 파일입니다.
    => 이미지 바이너리를 UTF-8로 변환 -> 불가능
    => '가'라는 것을 UTF-8로 변환 가능 -> 코드 포인트와 대응하는 인코딩 존재
    => 그러나 이미지 바이너리 자체 데이터에 대응되는 UTF-8 없을 수 있음 -> 인코딩 실패


4. Base_64 인코딩을 사용하는 이유
    4-1. 바이너리 데이터를 텍스트로 표현할 수 있습니다.
        => HTML/CSS에 작은 이미지를 Base_64 문자열로 직접 포함시킬 수 있습니다.
        => JSON API에 이미지나 파일 데이터를 문자열 필드에 포함시킬 수 있습니다.
    4-2. 일부 전송 환경에서 데이터 표현을 안정적으로 처리할 수 있습니다.


5. Base_64 인코딩의 단점
    5-1. 데이터 크기가 약 33% 증가합니다.
        => 원본 이미지 크기가 3MB라면 Base_64 문자열이 4MB가 될 수 있습니다.
    5-2. 인코딩과 디코딩 추가 작업이 필요합니다.
        => 보내는 쪽 : 바이너리 데이터 → Base64 인코딩
        => 받는 쪽: Base64 문자열 → 바이너리 데이터로 디코딩
    5-3. 캐싱과 재사용에 불리할 수 있습니다.
