1. 프로세스 종류
    1-1. 사용자가 현재 직접 조작하고 있는 작업 공간에서 실행되는 프로세스를 포그라운드 프로세스라고 합니다.
    1-2. 사용자가 현재 직접 조작하지 않아도 뒤에서 계속 실행되는 프로세스를 백그라운드 프로세스라고 합니다.
        => 백그라운드 프로세스 중 사용자와 직접 상호작용 가능한 백그라운드 프로세스도 있고 사용자와 상호작용 하지 않고 정해진 일만 수행하는 백그라운 프로세스가 있습니다.
        => 사용자와 직접 소통하지 안혹 정해진 일만 수행하는 백그라운 프로세스 -> 유닉스 체계에서는 데몬이라고 부르고 윈도우에서는 서비스라고 부릅니다.


2. 프로세스 제어 블록
    2-1. 모든 프로세스는 CPU를 필요로 하지만 CPU 자원은 한정되어 있습니다.
        => 프로세스들은 차례대로 돌아가며 한정된 시간만큼만 CPU를 사용합니다.
        => 프로세스가 CPU를 사용하다가 할당된 시간이 끝나면 인터럽트(타이머 인터럽트)가 발생하면 다음 프로세스에게 자원을 넘깁니다.
        => 이를 위해서 프로세스 제어 블록(PCB)을 이용합니다.

    2-2. 프로세스 제어 블록은 프로세스와 관련된 정보를 저장하는 자료 구조입니다.
        => PCB는 해당 프로세스를 식별하기 위해 필요한 정보들이 저장됩니다.
        => PCB는 커널 영역에 생성됩니다. 
        => PCB는 프로세스 생성 시에 만들어지고 실행이 끝나면 폐기됩니다.
    
    2-3. PCB 정보
        1. 프로세스 ID (PID)
            => 특정 프로세스를 식별하기 위해 부여하는 고유한 번호입니다.
        2. 레지스터 값
            => 자신의 실행 차례가 돌아오면 이전까지 사용했던 레지스터 중간값들을 모두 복원합니다.
        3. 프로세스 상태

        4. CPU 스케줄링 정보
            => 프로세스가 언제, 어떤 순서로 CPU를 할당받을지에 대한 정보
        5. 메모리 관리 정보
            => 프로세스마다 메모리에 저장된 위치가 다릅니다
            => PCB는 프로세스가 어느 주소에 저장되어 있는지에 대한 정보가 있어야 합니다.
        6. 사용한 파일과 입출력장치 목록
            => 프로세스 실행 과정에서 특정 입출력장치나 파일을 사용하면 PCB에 해당 내용이 명시됩니다.


3. 문맥 교환 (Context Switch)
    => a가 운영체제로부터 cpu를 할당받아 실행되다가 시간이 다 되어 프로세스 b에 cpu 사용을 양보한다고 가정
    => a는 프로그램 카운터, 각종 레지스터 값, 메모리 정보, 실행을 위해 열었던 파일, 사용한 입출력 장치 등을 백업해야 합니다. -> 다음 차례에 이어서 실행해야 함
    => 하나의 프로세스 수행을 재개하기 위해 기억해야 할 정보를 문맥(context)라고 합니다.
    => 하나의 프로세스 문맥은 해당 프로세스의 PCB에 표현되어 있습니다.

    => 기존 프로세스 문맥을 PCB에 백업하고, 새로운 프로세스를 실행하기 위해 문맥을 PCB로부터 복구하여 새로운 프로세스를 실행하는 것
        ==> 문맥 교환이라고 합니다.


4. 프로세스의 메모리 영역
    => 사용자 영역에 프로세스는 크게 코드 영역/ 데이터 영역/ 힙 영역/ 스택 영역으로 나뉘어 저장됩니다.

    4-1. 코드 영역 (텍스트 영역)
        => 기계어로 이루어진 명령어가 저장됩니다.
        => CPU가 실행할 명령어가 담겨 있기 때문에 쓰기가 금지되어 있는 read-only 공간입니다.
        => 할당 받은 메모리 영역의 크기가 변하지 않습니다.
    
    4-2. 데이터 영역
        => 프로그램이 실행되는 동안 데이터가 저장되는 공간입니다. (전역변수)
        => 할당 받은 메모리 영역의 크기가 변하지 않습니다.
    => 코드 영역과 데이터 영역은 크기가 고정된 영역이라는 점에서 정적 할당 영역이라고 부릅니다.

    4-3. 힙 영역
        => 프로그램을 만드는 사용자가 직접 할당할 수 있는 공간입니다.
        => 메모리 공간을 반환할 의무가 있고 반환하지 않는다면 메모리 누수가 발생합니다.
    
    4-4. 스택 영역
        => 데이터가 일시적으로 저장되는 공간입니다.
        => 함수의 실행이 끝나면 사라지는 매개변수, 지역 변수..
    => 힙 영역과 스택 영역은 실시간으로 크기가 변할 수 있기 때문에 동적 할당 영역이라고 합니다.

    4-5. 힙 영역은 메모리의 낮은 주소에서 높은 주소로 할당되고, 스택 영역은 높은 주소에서 낮은 주소로 할당됩니다.
        => 크기가 동적이라 새롭게 할당되는 주소가 겹칠일을 없게 하려고
