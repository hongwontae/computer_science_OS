1. C/C++ 실행 파일
    1-1. 실행 파일은 기계어 뿐만 아니라 프로그램을 실행하기 위해 
            여러 정보가 정해진 형식에 따라 저장된 바이너리 파일입니다.
    
    1-2. C/C++ 파일 -> 실행 파일 과정
        => 전처리 -> 컴파일 -> 링킹 -> 실행 파일 생성
    

2. windows 실행 파일은 PE 형식을 사용합니다.
    2-1. PE(Portable Executable)는 실행 파일 내부에 어떤 정보가 어디에 저장되어 있는지 정의한 규칙입니다.

    2-2. 파일 형식이란?
        => 컴퓨터 입장에서 파일은 바이트들의 연속적인 데이터입니다.
        => 48 65 6C 6C 6F
        => ASCII로 해석하면 Hello입니다.
        => 중요한 것은 바이트 자체에는 이것이 문자열인지, 이미지인지, 실행 프로그램인지 전혀 있지 않습니다.
        => 파일 형식이란 바이트 데이터의 어떤 위치에 어떤 정보가 존재하고, 그 정보를 어떻게 해석해야 하는지를 정의한 규칙입니다.
    
    2-3. 확장자란?
        => 확장자는 파일 이름의 일부이며, 사람과 OS가 파일의 용도를 쉽게 구분하도록 도와주는 표시입니다.
    
    2-4. PE 구조는 크게 헤더, 섹션 테이블, 섹션으로 구분합니다.
        => 헤더 : 실행 파일이 어떤 파일이고, 어떻게 메모리에 배치되어야 하는지 설명하는 정보
        => 섹션 테이블 : 각 섹션의 파일 내 위치, 크기, 메모리 주소 등의 정보
        => 섹션 : 실제 기계어 명령어, 초기화 데이터, 읽기 전용 데이터 등이 저장된 영역
    
    2-5. Windows SDK
        => PE 형식을 설명하기 위해 그 규칙을 C/C++ 타입으로 표현한 것입니다.


3. PE 파일 헤더 구조

    3-1. PE 헤더는 CPU가 직접 실행할 명령어가 아니라 OS가 실행 파일을 이해하고 메모리에 배치하는데 사용하는 정보입니다.

    3-2. DOS Header
        1. 구조체 이름은 IMAGE_DOS_HEADER입니다.
        2. PE 파일 맨 앞에 존재합니다.
        
        3. 두 가지 필드가 존재합니다.
        필드	    크기	     역할
        e_magic	    2바이트	    DOS 실행 파일을 식별하는 MZ 서명
        e_lfanew	4바이트	    NT Headers가 시작되는 파일 위치

        3-1. e_magic
            => PE 파일 첫 두 바이트에는 일반적으로 4D 5A 이 값이 들어있습니다.
            => ASCII로 해석하면 MZ, windows가 실행 파일을 분석할 떄 중요한 식별 정보입니다.
        
        3-2. e_lfanew
            => 파일 시작 위치로부터 NT Headers가 얼마나 떨어져 있는지를 나타내는 값입니다.
            => 운영체제가 e_lfanew를 읽으면 NT Headers가 어디에 있는지 알 수 있습니다.
                -> 그 위치에는 PE\0\0 서명이 존재해야 합니다.
    
    3-3. NT Header 
        => Windows SDK에서는 64비트 PE 이미지의 NT Headers를 다음과 같은 C 구조체로 표현합니다.
        typedef struct _IMAGE_NT_HEADERS64 {
            DWORD Signature; 
            IMAGE_FILE_HEADER FileHeader;
            IMAGE_OPTIONAL_HEADER64 OptionalHeader;
        } IMAGE_NT_HEADERS64;

        1. DWORD Signature;
            => DWORD는 32비트 부호 없는 정수 타입입니다.
            => 이 필드에는 네 바이트가 존재합니다. -> 50 45 00 00 -> ASCII -> P E \0 \0
            => 운영체제는 이 값을 통해 PE 형식의 서명을 확인할 수 있습니다.
        
        2. IMAGE_FILE_HEADER (COFF File Header라고도 부릅니다.) (파일의 기본 정보)
        
            typedef struct _IMAGE_FILE_HEADER {
            WORD  Machine;
            WORD  NumberOfSections;
            DWORD TimeDateStamp;
            DWORD PointerToSymbolTable;
            DWORD NumberOfSymbols;
            WORD  SizeOfOptionalHeader;
            WORD  Characteristics;
            } IMAGE_FILE_HEADER;

            => WORD는 16비트, DWORD는 32비트 정수입니다.

            => 각 필드의 의미
            필드	                      설명
            Machine	                    어떤 CPU 아키텍처를 대상으로 만들었는지
            NumberOfSections	        섹션의 개수
            TimeDateStamp	            파일 생성 시각 정보
            PointerToSymbolTable	    COFF 심볼 테이블 위치
            NumberOfSymbols	COFF        심볼 개수
            SizeOfOptionalHeader	    Optional Header의 크기
            Characteristics	            실행 이미지 여부 등 파일 속성 플래그
            
            => machine에는 아래의 값이 들어갈 수 있습니다.
            => 0x014C: Intel x86, 0x8664: AMD64(x86-64), 0xAA64: ARM64
            => NumberOfSections = 4라면 섹션 테이블에 네 개의 섹션 헤더가 있다는 뜻입니다.
            => 일반적인 현대 PE 이미지에서 COFF 심볼 테이블 관련 두 필드는 대체로 0입니다.
        
        3. Optional Header (실제 실행에 중요한 정보)
            => Optional인 이유는 COFF 오브젝트 파일(.obj)에는 일반적으로 필요하지 않기 때문입니다.
            => Optional Header는 크게 세 부분으로 나뉘어집니다.
                Standard Fields — 기본 실행 정보
                Windows-Specific Fields — Windows에서 실행하는 데 필요한 정보
                Data Directories — Import, Export 등 특수 테이블의 위치 정보
            
            => 대표적인 필드
            필드	                 역할
            Magic	                PE32 / PE32+ 형식 구분
            AddressOfEntryPoint	    실행 진입점의 RVA
            ImageBase	            선호하는 이미지 로드 기준 주소
            SectionAlignment	    메모리에서 섹션을 정렬하는 단위
            FileAlignment	        파일 내부에서 섹션 데이터를 정렬하는 단위
            SizeOfImage	            메모리에 매핑될 이미지의 전체 크기
            SizeOfHeaders	        파일 헤더 영역의 정렬된 크기
            Subsystem	            콘솔 프로그램인지 GUI 프로그램인지 등의 실행 환경
            SizeOfStackReserve	    초기 스택을 위해 예약할 가상 주소 공간 크기

            => ImageBase
            => 실행 파일을 프로세스의 가상 주소 공간에 매핑할 때 선호하는 시작 주소
            => ASLR 등의 이유로 실제 로드 주소는 달라질 수 있습니다.

            => AddressOfEntryPoint
            => 이 값은 실행이 시작될 진입점의 RVA를 나타냅니다.
            => ImageBase = 0x140000000, AddressOfEntryPoint = 0x1000
            => 이미지가 선호 주소에 로드되었다면 진입점의 가상 주소는
            => 0x140000000 + 0x10000x140001000
            => 입점이 반드시 C/C++의 main() 함수인 것은 아닙니다.

            => SizeOfImage
            => 프로그램 이미지가 메모리에 매핑될 때 차지하는 전체 가상 주소 범위의 크기
            => SizeOfImage = 0x5000
            => 헤더와 섹션들을 포함한 PE 이미지의 메모리 배치 크기가 0x5000바이트

            => Data Directories
            => Optional Header 안에는 Data Directory 배열이 존재합니다.
            => 각종 특수 테이블의 위치와 크기를 기록합니다.
            디렉터리	                용도
            Import Table	        외부 DLL에서 가져오는 함수 등의 정보
            Export Table	        외부에 제공하는 함수 등의 정보
            Resource Table	        아이콘, 문자열 등의 리소스
            Base Relocation Table	이미지 로드 기준 주소가 변경될 때 필요한 재배치 정보
            TLS Table	            스레드 로컬 저장소 관련 정보
