1. 명령어 사이클
    => CPU가 하나의 명령어를 처리하는 정형화된 흐름을 명령어 사이클이라고 합니다.


2. 인터럽트
    => CPU의 작업을 발해하는 신호를 인터럽트라고 합니다. (CPU가 얼른 처리해야 할 다른 작업이 존재할 떄 주로 발생)
    => 인터럽트의 종류에는 크게 동기 인터럽트(예외), 비동기 인터럽트(하드웨어 인터럽트)가 있습니다.
    
    2-1. 동기 인터럽트는 CPU에 의해 발생하는 인터럽트입니다.
        => CPU가 명령어들을 수행하다가 예상치 못한 상황에 마주쳤을 때 == CPU가 실행하는 프로그래밍상의 오류와 같은 예외적인 상황을 마주쳤을 때
        => 위 상황에 발생하는 인터럽트가 동기 인터럽트입니다. 그래서 예외라고 부르기도합니다. -> CPU가 메모리 접근했는데 원하는 데이터가 없음

    3-1. 비동기 인터럽트는 주로 입출력장치에 의해 발생하는 인터럽트입니다. -> 알림 역할
        => 키보드/마우스 같은 입출력장치가 어떠한 입력을 받아들였을 때 CPU에게 인터럽트를 보냅니다.
        => 일반적으로 비동기 인터럽트를 인터럽트로 칭합니다.

    3-2. 하드웨어 인터럽트
        => 입출력장치는 CPU보다 속도가 현저히 느립니다. 인터럽트가 없다면 프린트 작업의 결과를 확인하기 위해 주기적으로 확인을 해야합니다.
        => 이러한 작업은 CPU 사이클 낭비로 이어집니다. -> 입출력이 완료 -> 알림 발생 -> 이 과정이 더 효율적입니다.
        => 입출력 작업 도중에도 효율적으로 명령어를 처리하기 위해 하드웨어 인터럽트를 사용합니다.
    
    3-3. 하드웨어 인터럽트 처리 순서
        1. 입출력장치는 CPU에게 인터럽트 요청 신호를 보냅니다.
            => 인터럽트 요청 신호 : 하드웨어 인터럽트를 보내는 입출력 장치가 CPU에게 인터럽트 가능여부를 요청하는 신호입니다.

        2. CPU는 실행 사이클이 끝나고 명령어를 인출하기 전 항상 인터럽트 여부를 확인합니다.

        3. CPU는 인터럽트 요청을 확인하고 인터럽트 플래그를 통해 현재 인터럽트를 받아들일 수 있는지 여부를 확인합니다.
            => 플래그 레지스터의 인터럽트 플래그는 하드웨어 인터럽트를 받아들일지 무시할지 결정하는 플래그입니다.
            => CPU가 중요한 작업 처리 / 어떤 방해도 받지 않아야 할 떄 불가능으로 설정됩니다.
            => 인터럽트 플래그가 불가능이어도 무시할 수 없는 인터럽트 요청도 있습니다.
            => 정전이나 하드웨어 고장으로 인한 인터럽트가 이에 해당합니다.
            => 인터럽트 플래그로 막을 수 있는 인터럽트(maskable interrupt), 막을 수 없는 인터럽트(non maskable interrupt)

        4. 인터럽트를 받아들일 수 있다면 CPU는 지금가지의 작업을 백업합니다.
            => 인터럽트 서비스 루틴을 실행하기 전에 Stack 영역에 작업 내역들을 백업합니다. (프로그램 카운터 값, 메모리 주소 레지스터 값..)

        5. CPU는 인터럽트 백터를 참조하여 인터럽트 서비스 루틴을 실행합니다.
            => 인터럽트 서비스 루틴(인터럽트 핸들러) : 인터럽트를 처리하기 위한 프로그램입니다.
            => 인터럽트 요청을 보냈을 떄 해당 인터럽트를 어떻게 처리하고 작동해야 할지에 대한 정보로 이루어진 프로그램입니다.
            => "키보드가 인터럽트 요청을 보내면 .. 행동한다." 
            => 인터럽트 서비스 루틴은 프로그램이며 메모리에 존재합니다.
            => 이러한 인터럽트 서비스 루틴을 구분해야 하며 이를 구분하기 위해 인터럽트 백터가 존재합니다.
            => 인터럽트 백터 : 인터럽트 서비스 루틴을 식별하기 위한 정보입니다.
            => 입출력 장치가 인터럽트를 발생시켰을 떄 데이터 버스를 통해 해당 인터럽트 백터를 전달합니다.

        6. 인터럽트 서비스 루틴 실행이 끝나면 4에서 백업해 둔 작업을 복구하여 실행을 재개합니다.

        7. 총 흐름
            => 프로그램이 실행되고 RAM에서 명령어들을 가져와서 CPU가 실행합니다.
            => 이 때 입출력 장치에서 인터럽트 요청 신호 + 데이터 버스에서 인터럽트 백터가 전달됩니다.
            => 플래그 레지스터의 인터럽트 플래그가 받아들일 수 있는지 여부를 확인합니다.
            => 가능하다면 기존의 작업들을 Stack 영역에 저장합니다.
            => 인터럽트 백터를 통해 RAM에 존재하는 인터럽트를 발생시킨 입출력 장치에 해당하는 인터럽트 서비스 루틴 시작 주소를 찾습니다.
            => 인터럽트 서비스 루틴의 주소를 프로그램 카운터에 놓고 CPU가 실행합니다.
            => 인터럽트를 처리하고 나면 Stack에 저장해 둔 값을 다시 불러온 뒤 이전까지 수행하던 작업을 재개합니다.
