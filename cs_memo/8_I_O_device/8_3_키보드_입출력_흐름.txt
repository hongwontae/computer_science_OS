1. 키보드에서 a라는 키를 누릅니다.
    => 키보드의 회로가 해당 키의 눌림을 감지합니다.
    => 키보드 컨트롤러(마이크로 컨트롤러)는 USD HID 규격에 맞는 입력 데이터로 구성합니다.
        -> 키보드 내부 컨트롤러는 대체로 마이크로 컨트롤러를 사용합니다.
    => 키보드 컨트롤러는 입력이 A라는 것을 판단하고 USB HID 규격에 따라 A키에 해당하는 코드인 0x04를 입력 보고서에 기록합니다.
    => 0x04는 USB HID 규격에서 정한 a 키 식별 번호입니다. -> Usage ID
    => 입력 보고서는 수정 키 상태(shift, ctrl, alt.. 눌림 상태), 예약 필드, 일반 키의 Usage ID(키 코드)
    => 일반 키의 Usage ID 코드를 담는 공간은 동시 입력을 고려해서 6byte 공간입니다.
    => 입력 보고서는 대체로 8byte로 구성되어 있습니다.
    => 수정 키 상태-1byte / 예약-1byte / 일반 키 코드 (6byte)
    => 입력 보고서는 USB를 통해 컴퓨터에 전달합니다.
    
    ** USB HID 규격 **
        => USB : 컴퓨터와 주변 장치가 연결되고 데이터를 주고받는 인터페이스 규격
        => HID : 키보드, 마우스처럼 사람이 직접 조작하는 입력 장치의 종류
        => 규격이 없다면 제조사마다 키 입력 데이터를 다른 코드로 만들어내서 전달할 수 있습니다.
        => OS는 제조사별로 다른 처리 방법을 구현해야 합니다. -> 번거로움

        규격에서 정하는 내용	 의미
        Usage ID	        어떤 키나 버튼을 의미하는지 식별
        Report 형식	         데이터를 어떤 필드와 비트로 구성할지 정의
        Report Descriptor	장치가 어떤 데이터를 어떤 형식으로 보낼지 설명
        전송 방식	          USB를 통해 입력 보고서를 주고받는 방법


2. USB 호스트 컨트롤러가 데이터 전송을 처리합니다.
    => 컴퓨터의 USB 컨트롤러가 USB 통신을 관리합니다.
    => 일반적인 USB 키보드는 호스트가 주기적으로 입력 데이터를 확인하는 방식으로 동작합니다.


3. 하드웨어가 CPU에 처리할 데이터가 있음을 알립니다.
    => USB 호스트 컨트롤러는 전송 결과를 메모리 등에 기록하고, 인터럽트를 통해 CPU에 알릴 수 있습니다.
    => CPU는 현재 실행 중인 작업을 적절한 시점에 중단하고 커널의 인터럽트 처리 코드를 실행합니다.


4. 운영체제의 장치 드라이버가 데이터를 처리합니다.
    => USB 호스트 컨트롤러 드라이버가 전송 완료 등의 상태를 처리하고, USB 및 HID 드라이버 계층이 키보드 입력 데이터를 해석합니다.
    => 예를 들어 데이터에 특정 키가 눌렸다는 정보가 있다면, 운영체제의 입력 처리 계층으로 전달합니다.


5. 운영영체제가 입력 이벤트를 응용 프로그램에 전달합니다.
    => 운영체제는 키 입력을 입력 이벤트로 처리해 적절한 응용 프로그램에 전달해. 메모장은 이 이벤트를 받아 화면에 a를 표시합니다
    => 단, 실제 문자 결과는 Shift 키, Caps Lock, 키보드 배열, 입력기 상태 등에 따라 달라질 수 있습니다.
