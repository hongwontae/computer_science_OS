1. CPU와 입출력장치 간의 정보를 주고 받는 방식은 크게 세 가지 존재합니다.


2. 프로그램 입출력
    => 프로그램 속 명령어로 입출력장치를 제어하는 방법입니다.
    => CPU가 프로그램 속 명령어를 실행하는 과정에서 입출력 명령어를 만나면 CPU는 입출력장치에 연결된 장치 컨트롤러와 상호작용하며 입출력 작업을 수행합니다.
    
    2-1. 메모리에 저장된 벙보를 하드 디스크에 백업하는 상황
        1. CPU는 하드 디스크 컨트롤러의 제어 레지스터에 쓰기 명령을 보냅니다.
        2. 하드 디스크 컨트롤러는 하드 디스크 상태를 확인합니다. 하드 디스크가 준비된 상태라면 하드 디스크 컨트롤러는 상태 레지스터에 준비되었다고 표시합니다.
        3. CPU는 상태 레지스터를 주기적으로 읽어보며 하드 디스크의 준비 여부를 확인합니다.
            => 하드 디스크가 준비됐음을 CPU가 알게 되면 백업할 메모리의 정보를 데이터 레지스터에 씁니다.
            => 아직 백업 작업(쓰기 작업)이 끝나지 않았다면 1번부터 반복하고, 쓰기가 끝났다면 작업을 종료합니다.
        4. 프로그램 입출력 방식에서 입출력 작업은 CPU가 장치 컨트롤러의 레지스터 값을 읽고 씀으로써 이루어집니다.
            => CPU는 장치 컨트롤러의 레지스터들을 인식하는 방식은 크게 두 가지 있습니다.
    
    2-2. 메모리 맵 입출력
        => 메모리에 접근하기 위한 주소 공간과 입출력장치에 접근하기 위한 주소 공간을 하나의 주소 공간으로 간주하는 방법입니다.
        => 1024개의 주소를 표현할 수 있는 컴퓨터가 있을 떄 512는 메모리 주소 / 512는 장치 컨트롤러의 레지스터 주소
        => 이 떄 CPU는 메모리 주소들이나 장치 컨트롤러의 레지스터나 동일하게 메모리 주소를 대하듯 작업하면 됩니다.
    
    2-3. 고립형 입출력
        => 메모리를 위한 주소 공간과 입출력장치를 위한 주소 공간을 분리하는 방법입니다.
        => 대전제 : 데이터를 저장하는 물리적 공간은 다릅니다. 메모리/데이터 && I/O장치/데이터
        => 이 떄 컴퓨터가 표현할 수 있는 주소 범위가 한정적이라면 주소 번호를 나누는게 아니라 제어 신호로 어느 공간의 주소인가를 구별합니다.
        => 제어 버스가 메모리 쓰기/읽기 신호일 떄는 주소 버스를 통해서 들어온 100이 메모리의 100 주소입니다.
        => 제어 버스가 입출력 쓰기/읽기 신호일 때는 주소 버스를 통해서 들어온 100이 입출력장치의 100의 주소입니다.
    

3. 인터럽트 기반 입출력
    => 입출력장치에 의한 하드웨어 인터럽트는 사실 장치 컨트롤러에 의한 하드웨어 인터럽트입니다.
    => CPU는 장치 컨트롤러에 입출력 작업을 명령하고 / 장치 컨틀롤러가 입출력장치 제어하고 입출력 수행하는 동안 CPU는 다른 작업
    => 입출력 작업 종료 -> 장치 컨틀로러 CPU에게 인터럽트 신호 발생 -> 인터럽트 서비스 루틴 실행
    => 인터럽트를 기반으로 하는 입출력을 인터럽트 기반 입출력이라고 합니다.

    => 여러 입출력장치에서 동시에 인터럽트가 발생하는 경우
    => CPU가 플래그 레지스터 속 인터럽트 비트를 비활성화한 채 인터럽트 처리하는 경우는 순차적으로 하드웨어 인터럽트를 처리합니다.

    => 현실적으로 인터럽트를 전부 순차적으로 해결할 수 없습니다.
    => CPU는 인터럽트 간에 우선순위를 고려하여 우선순위가 높은 인터럽트 순으로 여러 인터럽트를 처리해야 합니다.
    => 플래그 레지스터 속 인터럽트 비트가 활성화되어 있는 경우 / 인터럽트 비트를 비활성화해도 무시할 수 없는 인터럽트(Non-Maskable Interrupt)
        의 경우 CPU는 우선순위가 높은 인터럽트부터 처리합니다.
    => 이 떄 프로그래머블 인터럽트 컨트롤러(PIC) 하드웨어를 사용합니다.
    => PIC는 여러 장치 컨트롤러에 연결되어 장치 컨트롤러에서 보낸 하드웨어 인터럽트 요청들의 우선순위를 판별한 뒤 CPU에 지금 처리해야 할 하드웨어 인터럽트를 알려주는 장치입니다.
    => PIC 다중 인터럽트 처리 과정
        1. PIC가  장치 컨트롤러에서 인터럽트 요청 신호들을 받아들입니다.
        2. PIC는 인터럽트 우선순위를 판단한 뒤 CPU에 처리해야 할 인터럽트 요청 신호를 보냅니다.
        3. CPU는 PIC에 인터럽트 확인 신호를 보냅니다.
        4. PIC는 데이터 버스를 통해 인터럽트 백터를 보냅니다.
        5. CPU는 인터럽트 백터를 통해 인터럽트 요청의 주체를 알게되고, 해당 장치의 인터럽트 서비스 루틴을 실행합니다.


4. DMA 입출력
    => 입출력장치와 메모리가 CPU를 거치지 않고 상호작용할 수 있는 입출력 방식 -> DMA / DMA 입출력을 위해서는 시스템 버스와 연결된 DMA 컨트롤러 필요
    => 프로그램 기반 입출력 + 인터럽트 기반 입출력 -> 데이터 이동 + 이동하는 데이터 CPU를 거칩니다.
    => 입출력장치와 메모리 사이에 전송되는 모든 데이터가 CPU를 거친다면 -> 효율이 하락합니다.

    4-1. DMA 입출력 과정
        1. CPU는 DMA 컨트롤러에 하드 디스크 주소, 수행할 연산, 백업할 내용이 저장된 메모리 주소 등의 정보와 함께 입출력 작업을 명령합니다.
        2. DMA 컨트롤러는 CPU를 거치지 않고 메모리와 직접 상호작용하며 백업할 정보를 읽어오고 이를 하드 디스크의 장치 컨트롤러에 내보냅니다.
        3. 백업이 끝나면 DMA 컨트롤러는 CPU에게 인터럽트를 걸어 작업이 끝났음을 알립니다.
            => 여기서 CPU는 오로지 입출력의 시작과 끝에만 관여합니다.
    
    4-2. 시스템 버스 문제
        => DMA 컨트롤러는 시스템 버스로 메모리에 직접 접근 가능 -> 시스템 버스는 동시 사용 불가
        => DMA 컨틀롤러는 CPU가 시스템 버스를 이용하지 않을 때마다 조금씩 시스템 버스 이용 or CPU에게 일시적으로 시스템 버스 이용하지 않도록 허락 구하고 집중적으로 사용
        => 이러한 DMA 버스 이용을 사이클 스틸링이라고 부릅니다.
    
    4-3. 입출력 버스
        => 메모리에서 DMA 컨트롤러로 데이터를 가져오기 위해 시스템 버스 사용
        => DMA 컨틀로러의 데이터를 장치 컨트롤러로 옮기기 위해 시스템 버스 사용
        => DMA가 시스템 버스를 자주 사용하면 그만큼 CPU가 시스템 버스를 이용하지 못합니다.
        => DMA 컨트롤러와 장치 컨트롤러들을 입출력 버스라는 별도의 버스로 연결하여 해결합니다.
        => DMA 컨트롤러와 장치 컨트롤러가 서로 데이터를 주고 받을 때 시스템 버스를 사용할 필요가 없어집니다.
        => 현대에는 컴퓨터에는 입출력 버스가 있고 입출력장치는 입출력 버스와 연결됩니다.
