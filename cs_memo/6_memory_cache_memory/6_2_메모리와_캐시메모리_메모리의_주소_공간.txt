1. 물리 주소와 논리 주소
    => 물리 주소 : 하드웨어상 주기억장치의 주소를 의미합니다.
    => 논리 주소 : 실행 중인 프로그램 각각에게 부여된 0번지부터 시작되는 주소를 의미합니다.
    => 이렇게 나눈 이유는 프로그램이 RAM의 실제 위치에 신경 쓰지 않아도 되기 때문입니다.
    => 또한 메모리에 저장된 정보는 시시각각 변합니다. 
        => 메모리에는 프로그램이 적재되고 사라지기를 반복합니다. -> CPU와 프로그램이 실 메모리 주소를 지속적으로 추적하는게 힘듬
    => 프로그램마다 같은 논리 주소가 존재할 수 있습니다. -> CPU는 논리 주소를 받아들이고 해석하고 연산합니다.


2. MMU (Memory Management Unit)
    => CPU가 메모리와 상호작용하려면 논리 주소와 물리 주소간의 변환이 이루어져야 합니다.
    => 논리 주소와 물리 주소간의 변환은 CPU와 주소 버스 사이에 위치한 메모리 관리 장치(MMU)라는 하드웨어 의해 실행됩니다.
    => MMU는 CPU가 발생시킨 논리 주소에 베이스 레지스터 값을 더하여 논리 주소를 물리 주소로 변환합니다.
        => 베이스 레지스터는 프로그램의 첫 물리 주소를 저장 / 논리 주소는 프로그램의 시작점으로부터 떨어진 거리
    => 프로그램 A의 100번지 데이터 삭제 명령 -> 베이스 레지스터 1500 / CPU가 발생시킨 논리주소 100 -> 15100 -> 실제 하드웨어 상 RAM 15100 삭제


3. 메모리 보호 기법
    => 다른 프로그램의 영역을 침범할 수 있는 명령어는 다른 프로그램에게 영향을 끼치기 때문에 보호할 방법이 필요합니다.
    => 프로그램 A 실제 RAM 주소(2000 ~ 2999) / CPU가 발생시킨 논리주소 1100 / 베이스 레지스터 2000 -> 3100 -> 다른 프로그램에 영향을 미쳐버림
    => 한계 레지스터가 이를 담당합니다.
    => 한계 레지스터는 논리 주소의 최대 크기를 저장합니다. 한계 레지스터 크기 == RAM에 저장된 실행중인 프로그램 크기
    => 프로그램 B 실제 RAM 주소 (1500 ~ 2500) / 베이스 레지스터 (1500), CPU가 발생시킨 논리 주소 (1200), 한계 레지스터 (1000) -> 2200 -> 한계 레지스터보다 위 -> 실패
    => CPU는 메모리에 접근하기 전에 접근하고자 하는 논리 주소가 한계 레지스터보다 작은지 항상 검사합니다.
    => 만약 CPU가 한계 레지스터보다 높은 논리 주소에 접근하려고 하면 인터럽트(트랩)를 발생시켜 실행을 중단시킵니다.
