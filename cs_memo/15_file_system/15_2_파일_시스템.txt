1. 파일 시스템
    => 파일과 디렉터리를 보조기억장치에 효울적으로 저장하고 접근할 수 있게 하는 OS 내부의 프로그램입니다.
    => 파일 시스템은 다양한 종류가 있고, 하나의 컴퓨터에서 여러 파일 시스템을 사용할 수 있습니다.


2. 파티셔닝과 포매팅
    => 한 번도 사용되지 않은 HDD, SSD는 곧바로 파일을 생성하거나 저장할 수 없습니다.
    => 보조기억장치를 사용하려면 파티션을 나누는 작업과 포맷 작업을 거쳐야 합니다.
    
    2-1. 파티셔닝
        => 저장 장치의 논리적인 영역을 구획하는 작업입니다.
        => 파티셔닝 작업을 통해 나누어진 영역 하나하나를 파티션이라고 합니다.
    
    2-2. 포매팅
        => 파일 시스템을 설정하여 어떤 방식으로 파일을 저장하고 관리할 것인지 결정하고
            새로운 데이터를 쓸 준비를 하는 작업을 의미합니다.
        => 어떤 종류의 파일 시스템을 사용할지는 이 떄 결정합니다.
        => 파티션마다 다른 파일 시스템을 설정할 수 도 있습니다.


3. 파일 할당 방법
    => OS는 파일과 디렉터리를 블록 단위로 읽고 씁니다. 
    => 블록은 위치를 식별하는 주소가 존재합니다.
    => 파일을 보조기억장치에 할당하는 방법은 크게 연속 할당과 불연속 할당이 있고 불연속 할당에는 연결 할당, 색인 할당이 있습니다.

    3-1. 연속 할당
        => 보조기억장치 내 연속적인 블록에 파일을 할당하는 방식입니다.
        => 연속적으로 할당된 파일에 접근하기 위해서는 파일의 첫 번째 블록의 주소와 길이만 알면 됩니다.
        => 연속 할당은 외부 단편화를 야기합니다.
        => 중간에 3 블록 파일을 삭제하고 5블록을 추가하려고 한다면? -> 중간 3 블록에 넣을 수 없습니다.
    
    3-2. 연결 할당
        => 각 블록 일부에 다음 블록의 주소를 저장하여 각 블록이 다음 블록을 가리키는 형태로 할당하는 방식입니다.
        => 즉, 파일을 이루는 데이터를 연결 리스트로 관리합니다.
        => 마지막 블록에는 다음 블록이 없다는 특별한 표시자를 기록합니다.

        => 외부 단편화 문제를 해결하지만 단점이 있습니다.
            1. 반드시 첫 번째 블록부터 차례대로 읽어야 합니다.
                => 중간 부분부터 접근하고 싶어도 첫 번째 블록부터 접근해서 읽어야 합니다.
                => 임의 접근 속도가 매우 느립니다.
            2. 하드웨어 고장이나 오류 발생 시 해당 블록 이후 블록은 접근할 수 없습니다.
                => 블록 안에 파일 데이터와 다음 블록 주소가 모두 포함되어 있어 블록 하나의 이상이
                    생기면 다음 블록에 접근할 수 없습니다.
    
    3-3. 색인 할당
        => 파일의 모든 블록 주소를 색인 블록이라는 하나의 블록에 모아 관리하는 방식입니다.
        => 색인 할당은 파일 내 임의의 위치에 접근하기 쉽습니다.
        => 색인 블록을 사용하는 파일 시스템은 디렉터리에 파일 이름과 색인 블록 주소를 명시합니다.


4. 파일 시스템 살펴보기
    => USB 메모리, SD 카드 등의 저용량 장치에서는 사용되는 FAT 파일 시스템
    => 유닉스 계열 OS에서 사용되는 유닉스 파일 시스템

    4-1. FAT 파일 시스템
        => 각 블록에 다음 블록의 주소들을 한데 모아 테이블 형태로 관리하면 연결 할당의 단점을 상당 부분 해결할 수 있습니다.
            -> 이 같은 테이블을 파일 할당 테이블(FAT)이라고 합니다.
            -> 이 FAT을 이용하는 파일 시스템이 FAT 파일 시스템 입니다.
        => 윈도우에서는 블록이라는 용어 대신 클러스터라는 용어를 사용합니다.
        => 하드 디스크의 한 파티션을 FAT 파일 시스템을 포맷하면 예약 영역, FAT 영역, 루트 디렉토리 영역, 데이터 영역으로 나뉘어집니다.
        => 데이터 영역은 서브 디렉터리와 파일들을 위한 영역입니다.
        
        => FAT은 실행도중 메모리에 캐시될 수 있습니다. 
        => 메모리에 적재된 채 실행되면 기존 연결 할당보다 다음 블록을 찾는 속도가 매우 빨라지고 임의 접근에도 유리해집니다.

        => FAT 파일 시스템의 디렉터리 엔트리에는 파일 이름, 첫 번쨰 블록 주소, 파일 속성이 있습니다.
    
    4-2. 유닉스 파일 시스템
        => 유닉스 파일 시스템은 색인 할당 기반이며, 색인 블록을 i-node라고 부릅니다.
        => i-node에는 파일 속성 정보와 열다섯 개의 블록 주소가 저장될 수 있습니다.
        => 파일마다 i-node가 존재하고, i-node마다 번호가 있습니다.
        => 하나의 파티션이 유닉스 파일 시스템을 사용하면 예약 영역, i-node 영역, 데이터 영역으로 나뉘어집니다.

        => i-node의 크기는 유한하기에 블록을 20, 30 차지하는 파일을 가리키기 위해 특별한 방법을 사용합니다.

            1. 블록 주소 중 열 두개에는 직접 블록 주소를 저장합니다.
                => 12개는 파일 데이터가 저장된 블록 주소가 직접적으로 명시됩니다.
                => 파일 데이터가 저장된 블록을 직접 블록이라고 합니다.
                => 즉, 12개는 직접 블록의 주소를 저장합니다.
                => 여기서 파일 데이터 블록을 모두 가리킬 수 있다면 추가적인 작업이 필요 없습니다.
            
            2. 1에서 충분하지 않다면 열세 번째 주소에 단일 간접 블록 주소를 지정합니다.
                => 단일 간접 블록은 파일 데이터를 저장한 블록 주소가 저장된 블록을 의미합니다. (이중 포인터)
            
            3. 2에서 충분하지 않다면 열네 번째 주소에 이중 간접 블록 주소를 저장합니다.
                => 이중 간접 블록은 단일 간접 블록의 주소를 저장하는 블록입니다. (삼중 포인터)
            
            4. 3에서 충분하지 않다면 열다섯 번쨰 주소에 삼중 간접 블록 주소를 저장합니다. (사중 포인터)
    
        => 유닉스 파일 시스템 디렉터리 엔트리는 i-node 번호와 파일 이름으로 구성되어 있습니다.
    

5. 마운트
    => 한 저장장치의 파일 시스템에서 다른 저장 장치의 파일 시스템에 접근할 수 있도록 파일 시스템을 편입시키는 작업을 의미합니다.
    => USB를 꽂았을 떄 내 컴퓨터에서 USB 파일에 접근할 수 있는 것 -> 마운트
