1. 프로세스 우선순위
    => 프로세스는 우선순위가 존재합니다. / CPU 사용 접근 순위가 프로세스마다 다릅니다.
    => 입출력 집중 프로세스 -> 입출력 작업이 많은 프로세스를 의미합니다. (비디오 출력, 하드 디스크 백업..)
    => CPU 집중 프로세스 -> CPU 작업이 많은 프로세스를 의미합니다. (복잡한 수학 연산, 컴파일, 그래픽 처리..)
    => 입출력 집중 프로세스는 실행 상태보다 입출력을 위한 대기 상태에 많이 머무릅니다. -> CPU를 단시간만 사용
    => 대체로 CPU 우선 순위는 입출력 집중 프로세스가 더 높습니다. 
        -> 입출력 집중 프로세스를 빠르게 실행시켜 대기 상태에 놓이게하고 다음 프로세스를 실행하는게 효율적입니다.
    => 위처럼 운영체제는 우선순위를 부여하는데 PCB에 우선순위를 명시하고 우선순위 기준으로 프로세스를 처리합니다.


2. CPU 버스트와 입출력 버스트
    => CPU를 이용하는 작업을 CPU 버스트 / 입출력장치를 기다리는 작업을 입출력 버스트라고 합니다.
    => 프로세스는 일반적으로 CPU 버스트와 입출력 버스트를 반복하며 실행됩니다.
    => 입출력 집중 프로세스 -> 입출력 버스트가 많은 프로세스 
    => CPU 집중 프로세스 -> CPU 버스트가 많은 프로세스


3. 스케줄링 큐
    => PCB에 우선순위가 존재하지만 OS가 CPU가 사용할 프로세스를 찾는 것은 비효율적입니다.
        -> 프로세스는 많고 새로운 프로세스가 생기거나 사라지거나 / 입출력장치, 보조기억장치 사용할 프로세스..
    => OS는 프로세스들에 줄을 서서 기다릴 것을 요구합니다. -> OS는 이 줄을 스케줄링 큐로 구현하고 관리합니다.
    => 하나의 큐에 모든 프로세스가 들어가는게 아니라 카테고리에 맞게 들어갑니다.
        -> 준비 큐에는 cpu 사용하고 싶은 프로세스끼리, 하드 디스크 사용하고 싶은 프로세스끼리, 프린터를 쓰고 싶은 프로세스끼리..
        -> 대기 큐에는 프린터 대기 큐, CD-ROM 대기 큐, 하드 디스크 대기 큐..
    => 큐는 자료구조 관점에서 먼저 삽입된 데이터가 먼저 나가는 선입선출 / 스케줄링 큐는 반드시 선입선출을 지키지는 않습니다.
    
    3-1. 운영체제가 관리하는 큐는 다양한 종류가 있습니다. 대표적으로 준비큐, 대기큐가 존재합니다.

    3-2. 준비 큐
        => CPU를 이용하고 싶은 준비 상태에 프로세스들이 서는 줄
    
    3-3. 대기 큐
        => 입출력장치를 이용하기 위해 대기 상태에 접어든 프로세스들이 서는 줄
    
    3-4. 흐름
        => 준비 상태인 프로세스들은 준비 큐에 들어갑니다.
        => 일반적으로 선입선출이지만 우선순위에 따라 cpu를 할당받은 프로세스가 달라질 수 있습니다.
        => 준비 큐에 준비 상태 프로세스가 CPU만 사용하면 실행 상태로 가고 타이머 인터럽트 발생 -> 준비 큐에 다시 들어갑니다.
        => 준비 큐에 준비 상태 프로세스가 입출력 장치를 사용하면 대기 상태로 가고 대기 큐에 들어갑니다. -> 입출력 작업 후 준비 상태로 들어갑니다.
        => PCB의 프로세스 상태를 먼저 바꾸고 큐에 들어갑니다.


4. 선점형과 비선점형 스케줄링
    4-1. 선점형 스케줄링
        => 프로세스가 CPU를 비롯한 자원을 사용하고 있더라도 OS가 프로세스로부터 
            자원을 강제로 빼앗아 다른 프로세스에 할당할 수 있는 스케줄링 방식을 의미합니다.
        => 프로세스마다 CPU 사용 시간이 정해져 있고 타이머 인터럽트 발생 후 OS가 
            다음 프로세스에게 CPU 할당하는 방식은 선점형 스케줄링의 일종입니다.
        => 자원 독점을 막고 골고루 자원을 분배 / 문맥 교환 과정에서 오버헤드 발생할 수 있음
    
    4-2. 비선점형 스케줄링
        => 하나의 프로세스가 자원을 사용하고 있다면 그 프로세스가 종료되거나 스스로 대기 상태에
            접어들기 전까진 다른 프로세스가 끼어들 수 없는 스케줄링 방식을 의미합니다.
        => 프로세스 자원 독점 현상 / 문맥 교환 과정에서 오버헤드 줄어들음
