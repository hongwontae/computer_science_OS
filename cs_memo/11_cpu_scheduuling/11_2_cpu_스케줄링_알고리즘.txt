1. 스케줄링 알고리즘
    => 프로세스가 큐에 존재할 떄 어떤 알고리즘으로 CPU를 프로세스에게 줄것인가?


2. 선입 선처리 스케줄링 (FCFS)
    => 준비 큐에 삽입된 순서대로 처리하는 비선점형 스케줄링입니다.
    => 먼저 CPU를 요청한 프로세스부터 CPU를 할당합니다.
    => 프로세스들이 기다리는 시간이 매우 길어질 수 있습니다. -> 이를 호위 효과라고 합니다.


3. 최단 작업 우선 스케줄링 (SJF)
    => 준비 큐에 삽입된 프로세스들 중 CPU 이용 시간의 길이가 제일 짧은 프로세스부터 실행하는 방식입니다. 
    => 기본적으로는 비선점형 스케줄링 알고리즘으로 분류됩니다.


4. 라운드 로빈 스케줄링 (RR)
    => 선입 선처리 + 타임 슬라이스
    => 타임 슬라이스 : 각 프로세스가 CPU를 사용할 수 있는 정해진 시간을 의미합니다.
    => 정해진 타임 슬라이스만큼의 시간 동안 돌아가며 CPU를 이용하는 선점형 스케줄링입니다.
    => 정해진 시간 모두 사용 -> 끝나지 않음 -> 다시 큐 맨 뒤에 삽입 합니다. (문맥 교환)
    => 타임 슬라이스 크기가 중요합니다. -> 크면 호위 효과, 작으면 문맥 교환 비용 상승


5. 최소 잔여 시간 우선 스케줄링 (SRT)
    => 최단 작업 우선 스케줄링 + 라운드 로빈 스케줄링
    => 정해진 시간만큼 CPU를 사용하되, 다음으로 CPU를 사용할 프로세스는 남은 작업 시간이 가장 적은 프로세스를 선택하는 방식입니다.


6. 우선순위 스케줄링
    => 프로세스 우선순위가 높은 프로세스부터 실행하는 방식입니다.
    => 우선순위가 같다면 선입 선처리 방식을 사용합니다.
    => 우선순위가 낮은 프로세스는 준비 큐에 먼저 삽입되었음에도 불구하고 우선순위가
         높은 프로세스들에 의해 실행이 계속 연기될 수 있습니다. -> 이를 기아 현상이라고 합니다.
    => 에이징 : 오랫동안 대기한 프로세스의 우선순위를 점차 높이는 방식입니다.


7. 다단계 큐 스케줄링
    => 우선순위 별로 준비 큐를 여러 개 사용하는 스케줄링 방식입니다.
    => 우선순위가 가장 높은 큐에 있는 프로세스를 먼저 처리하고 우선 순위 가장 높은 큐가 비어 있으면
         그 다음 우선순위 큐 프로세스를 처리합니다.
    => 큐를 여러 개 두면 프로세스 유형별로 우선순위를 구분하여 실행하는 것이 편리해집니다.
    => 우선순위가 높은 입출력 집중 프로세스 / 우선순위가 낮은 CPU 집중 프로세스..
    => 큐별로 타임 슬라이스 여러 개 지정 / 큐마다 다른 스케줄링 알고리즘..
    => 다단계 큐 스케줄링은 큐 간 프로세스 이동이 불가능해서 기아 현상이 발생할 수 있습니다.


8. 다단계 피드백 큐 스케줄링
    => 다단계 큐 스케줄링 + 큐 간에 프로세스가 이동할 수 있는 스케줄링 방식입니다.
    => 새로 생긴 프로세스가 있다면 우선 순위가 가장 높은 큐에 삽입 -> 타임 슬라이스 동안 실행
        -> 끝나지 않음 -> 바로 후 순위 큐에 삽입 -> 실행 -> 그 다음에도 끝나지 않음 -> 후 순위 큐에 삽입..
    => CPU를 오래 사용해야 하는 프로세스는 점차 우선순위가 낮아집니다.
    => 이 떄 낮은 우선순위 큐에서 오래 기다리고 있는 프로세스를 에이징을 통해 기아 현상을 예방할 수 있습니다.
    
    => 어떤 프로세스 CPU 이용 시간이 길면 낮은 우선순위 큐로 이동
    => 어떤 프로세스 낮은 큐에서 오래 기다리면 에이징으로 높은 우선순위로 이동
