1. 명령어 병렬 처리 기법
    => 명령어를 동시에 처리하여 CPU를 빈틈없이 작동시키는 기법을 의미합니다.
    => 명령어 처리 과정을 클럭 단위로 나눈다면
    => 명령어 인출 -> 명령어 해석 -> 명령어 실행 -> 결과 저장


2. 명령어 파이프라인
    => 하나의 명령어를 처리하는 전체 과정입니다.
    => 명령어 인출 -> 명령어 해석 -> 명령어 실행 -> 결과 저장
    => CPU는 같은 단계가 겹치지 않는다면 각 단계를 동시에 실행할 수 있습니다. (인출하는 동안 실행하거나 실행하는 동안 연산 결과 저장..)
    => 명령어 파이프라이닝 : 동시에 여러 개의 명령어를 겹쳐 실행하는 기법을 의미합니다.


3. 파이프라인 위험
    => 파이프라이닝이 특정 상황에서 성능 향상에 실패하는 경우를 의미합니다.
    
    3-1. 데이터 위험
        => 명령어 간 데이터 의존성에 의해 발생하는 위험입니다.
        => 어떤 명령어는 이전 명령어를 끝까지 실행해야만 실행할 수 있는 경우가 있습니다.
            => 명령어 1 : R1 : R2 + R3
            => 명령어 2 : R4 : R1 + R5
            => 명령어 1를 실행해야만 명령어 2를 인출할 수 있습니다.

    3-2. 제어 위험
        => 분기(Jump) 등으로 인한 프로그램 카운터의 갑작스러운 변화에 의해 발생합니다.
        => 프로그램 카운터는 현재 실행 중인 명령어의 다음 주소로 갱신됩니다.
        => 명령어 파이프라인은 대체로 순차적인 흐름에 의해서 설계됩니다. -> 1번지, 2번지..
        => 프로그램 카운터의 값의 갑작스러운 변경은 명령어 파이프라인에 미리 가지고 와서 처리 중이던 명령어들이 쓸모 없어지게 됩니다.
        => 분기 예측 : 프로그램이 어디로 분기할지 미리 예측한 후 그 주소를 인출하는 기술 -> 제어 위험 대처법
    
    3-3. 구조적 위험
        => 명령어들을 겹쳐 실행하는 과정에서 서로 다른 명령어가 동시에 ALU, Register 같은 CPU 부품을 사용하려고 할 떄 발생합니다.
    

4. 슈퍼스칼라
    => CPU 내부에 여러 개의 명령어 파이프라인을 포함한 구조를 슈퍼스칼라라고 합니다.
    => 멀티스레드 프로세서는 한 번에 여러 명령어 인출하거나 해석, 실행할 수 있습니다.
    => 이론적으로는 파이프라인 개수에 비례하여 프로그램 처리 속도가 빨리집니다.
    => 슈퍼스칼라 사용 -> CPU 파이프라인 위험에 노출될 확률이 높음
    => 실행 + 실행이 완벽히 겹쳤을 떄 -> 현대 CPU Core에는 ALU가 1개보다 많을 수 있음 -> 자동으로 해결 -> 만약 1개라면 기다림


5. 비순차적 명령어 처리 (OoOE)
    => 명령어를 순차적으로만 실행하지 않고 순서를 바꿔 실행해도 무방한 명령어를 
        먼저 실행하여 명령어 파이프라인이 멈추는 것을 방지하는 기법을 비순차적 명령어 처리라고 합니다.
    => 비순차적 명령어 처리 1을 보면 2가 처리되기 전까지 3,4,5,6은 기다려야 합니다. -> 데이터 의존성
    => 비순차적 명령어 처리2를 보면 명령어 순서를 바꿔서 파이프라인의 흐름을 막히지 않게 할 수 있습니다.
    => CPU가 명령어들이 어떤 명령어와 데이터 의존성을 가지고 있는지, 순서를 바꿔 실행할 수 있는 명령어는 무엇인지 판단할 수 있어야 합니다.
