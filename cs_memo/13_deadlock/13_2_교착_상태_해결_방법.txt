1. 교착 상태 예방
    => 교착 상태 발생 필요 조건 네 가지 중 하나를 충족하지 못하게 하는 방법입니다.

    1-1. 상호 배제 제거
        => 상호 배제 제거는 모든 자원을 공유하게 만듭니다.
        => 모든 자원의 상호 배제를 제거하는 것은 현실에서 무리가 있습니다.
        => 프린터기 하나 -> 이를 공유 자원으로?
    
    1-2.점유와 대기 제거
        => 점유와 대기 제거는 OS가 특정 프로세스에게 자원을 모두 할당하거나, 아예 할당하지 않는 방식으로 배분합니다.
        => 자원 활용률이 낮아지고, 당장 자원이 필요한 프로세스가 긴 대기 시간을 가져야 합니다.
    
    1-3. 비선점 조건 제거
        => 비선점 조건 제거하면 자원을 이용중인 프로세스로부터 다른 프로세스가 자원을 빼앗을 수 있습니다.
        => 프린터기 -> 작업 중에 다른 프로세스가 빼앗아 사용? -> 현실적으로 어려움
    
    1-4. 원형 대기 조건 제거
        => 원형 대기 조건 제거는 모든 자원에 번호를 붙이고 오름차순으로 자원을 할당하는 방식입니다.
        => 시스템 내에 존재하는 수많은 자원에 번호를 붙이는 일은 어렵고 번호를 설계가 복잡합니다.
    

2. 교착 상태 회피
    => 교착 상태가 발생하지 않을 정도로만 조심스럽게 자원을 할당하는 방식입니다.
    => 교착 상태를 한정된 자원의 무분별한 할당으로 인해 발생하는 것을 문제로 간주합니다.
    => 안전 순서열 : 교착 상태 없이 안전하게 프로세스들에 자원을 할당할 수 있는 순서를 의미합니다.
    => 안전 상태 : 교착 상태가 발생하지 않고 모든 프로세스가 정상적으로 자원을 할당받고 종료될 수 있는 상태
        -> 안전 순서열이 있는 상태를 안전 상태라고 볼 수 있습니다.
    => 불안전 상태 : 교착 상태가 발생할 수도 있는 상태
        -> 안전 순서열이 없는 상태를 불안전 상태라고 볼 수 있습니다.


3. 교착 상태 검출 후 회복
    => 교착 상태 발생을 인정하고 사후에 조치하는 방식입니다.
    => OS는 프로세스들이 자원을 요구할 떄마다 그때그떄 모두 할당하고 교착 상태 발생 여부를 주기적으로 검사합니다.
    => 그리고 교착 상태가 검출되면 2가지 방식으로 회복합니다.
    
    3-1. 선점을 통한 회복
        => 교착 상태가 해결될 떄까지 한 프로세스씩 자원을 몰아주는 방식입니다.
        => 교착 해결 전까지 다른 프로세스로부터 자원을 강제로 빼앗고 할당하는 방식입니다.
    
    3-2. 프로세스 강제 종료를 통한 회복
        => OS는 교착 상태에놓은 프로레스를 모두 강제 종료할 수도 있고, 교착 상태가 없어질 때까지 한 프로세스씩 강제 종료할 수도 있습니다.
        => 전자는 한 방에 교착 상태 해결할 수 있는 확실한 방법 / 많은 프로세스들이 작업 내역 잃게 될 가능성
        => 후자는 작업 내역을 잃는 프로세스는 최대한 줄일 수 있지만 / 교착 상태가 없어졌는지 여부를 확인하는 과정에서 오버헤드 야기
