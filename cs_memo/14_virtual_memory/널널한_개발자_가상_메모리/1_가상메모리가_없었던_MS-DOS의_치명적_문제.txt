**세그멘테이션**
    => 프로세스의 논리적인 구성 요소를 기준으로 나눕니다.
    => 마치, Text, Code, Heap, Stack처럼 논리적인 단위마다 별도의 영역을 부여하는 방식입니다.
    => 프로세스가 Text, Stack.. 세그먼트가 아닐 수 있습니다. -> 논리적 구성이나 목적에 따라 달라질 수 있습니다.
    => 세그먼테이션에서 환경에서 주소를 해석하려면 세그먼트 번호와 오프셋으로 찾을 수 있습니다.
    => 세그멘테이션이 메모리를 보호하는 로직
        1. 세그먼트 1이 시작 주소 1000 / 크기 500 / 쓰기 권한 허용
        2. 세그먼트 1에 접근하려고 할 떄 1100은 가능, 1600은 불가능 -> CPU가 접근 차단
        3. 또한 세그먼트 권한에 따라 쓰기는 가능 / 다른 것은 불가능 -> cpu가 반려
    => OS가 프로세스 생성 -> 세그멘테이션 기법을 사용하는 OS라면 세그멘테이션화 ->
        -> OS 영역에 메모리 관리 정보, 사용자 영역에 프로세스(데이터, 명령어) 
        -> 메모리 회수나 메모리 잘못된 접근 처리 가능
        

1. 과거에는 운영체제로 MS-DOS를 많이 사용했습니다.

2. 메모리 보호 : Process A가 Process B의 메모리 영역 침범을 막는 것입니다.
3. 메모리 회수 : Process A가 종료되거나 죽으면 그 RAM 공간을 회수하여 다른 프로세스가 사용할 수 있게 하는 것입니다.

4. 과거에는 프로세스가 물리 메모리에 직접 접근해서 사용했습니다.
    => 가상메모리 체계가 없던 MS-DOS 시절에는 프로세스가 비정상적을 종료되어도 위치를 식별할 수 없어
        프로세스가 전체의 시스템에 영향을 주었습니다. -> 과거에는 RAM 용량도 적은데 회수 실패시 치명적
    => 또한 Process가 뭉텅이로 올라오고 다른 프로세스에 접근하는 일도 있어서 비정상적으로 동작

5. CPU가 보호모드를 지원하기 시작하면서 Process끼리의 격리성이 올라갔습니다.

6. 보호 모드
    6-1. 권한 구분
        => 커널과 일반 프로그램의 권한을 구분합니다. 일반 프로그램이 OS 명령어 실행하면 CPU가 차단합니다.
    6-2. 메모리 접근 보호
        => 세그멘테이션이나 페이징 등의 기능을 통해 허용되지 않은 메모리 접근 차단합니다.
    6-3. 주소 변환 지원
        => 세그멘테이션과 페이징을 이용해 논리 주소 또는 가상 주소를 물리 주소로 변환할 수 있습니다.
    6-4. 인텔은 CPU가 보호 규칙을 검사하고 위반을 차단할 수 있는 회로와 상태 저장 장치를 CPU 내부에 설계했습니다.
