1. 프로그램 파일 자체를 미리 잘라서 보조기억장치에 저장해두지 않습니다.

2. 프로그램이 실행되어 프로세스가 만들어질 때, OS가 그 프로세스의 가상 주소 공간을 페이지 단위로 관리하는 것이 페이징의 핵심입니다.

3. 흐름
    3-1. SSD에 실행 파일이 존재합니다.
    3-2. 사용자가 실행 파일을 실행합니다.
    3-3. 프로세스에게 가상 주소 공간을 제공합니다.
    3-4. 프로그램의 코드/데이터가 가상 주소 공간에 배치될 수 있도록 구성합니다.
        => 즉, Code, Text, Stack, Heap..등의 메모리 위치를 가상 주소가 나타냅니다.
    3-5. CPU가 실행 파일을 실행하였기에 위의 작업이 된 프로세스가 RAM에 적재됩니다.


4. 흐름 + 페이징
    4-1. SSD에 실행 파일이 존재합니다.
    4-2. 사용자가 실행 파일을 실행합니다.
    4-3. 프로세스에게 가상 주소 공간을 제공하고 프로세스는 가상 주소가 코드/데이터/변수.. 등을 가리키도록 구성합니다.
        => 여기서 Stack, Heap, Code, Text.. 영역으로 나뉘는 것입니다.
    4-4. 그리고 가상 주소 공간을 가진 프로세스를 일정한 단위를 자른 하나를 페이지라고 합니다.
    4-5. 메모리의 물리 주소 공간도 일정한 단위로 자르고 이를 프레임이라고 합니다.
        => 여기서 페이지와 프레임의 크기는 일치해야 합니다.
    4-6. 이제 모든 프로세스를 올리지 않고 필요한 부분만 실행할 수 적재할 수 있고 불연속적으로 할당시킬 수 도 있습니다.
        => 이 떄 CPU의 순차적인 처리를 돕기 위해 페이지 테이블을 통해 연속적으로 실행시킬 수 있습니다.
