1. 요구 페이징
    1-1. 프로세스를 메모리에 적재할 떄 처음부터 모든 페이지를 적재하지 않고 필요한 페이지만을 메모리에 적재하는 기법입니다.
    
    1-2. 요구 페이징 흐름
        1. CPU가 특정 페이지에 접근하는 명령어를 실행합니다.
        2. 해당 페이지가 현재 메모리에 있을 경우(유효 비트 1) CPU는 페이지가 적재된 프레임에 접근합니다.
        3. 해당 페이지가 현재 메모리에 없을 경우 (유효 비트 0) 페이지 폴트가 발생합니다.
        4. 페이지 폴트 처리 루틴은 해당 페이지를 메모리에 적재하고 유효 비트를 1로 설정합니다.
        5. 다시 1을 수행합니다.
    
    1-3. 순수 요구 페이징
        => 아무런 페이지도 메모리에 적재하지 않은 채 무작정 실행합니다.
        => 프로세스의 첫 명령어를 실행한 순간부터 페이지 폴트 발생 -> 어느 정도 적재되면 페이지 폴트 빈도가 떨어집니다.
    
    1-4. 요구 페이징 시스템이 안정적으로 작동하려면 페이지 교체와 프레임 할당을 처리해야 합니다.


2. 페이지 교체 알고리즘
    2-1. 페이지를 물리 메모리에 적재하다보면 가득 차게 됩니다.
        => 이 떄 당장 실행에 필요한 페이지를 적재하기 위해 메모리에 적재된 페이지를 보조기억장치로 내보내야 합니다.
        => 이를 결정하는 방법이 페이지 교체 알고리즘입니다.
    
    2-2. 일반적으로 페이지 폴트를 가장 적게 일으키는 알고리즘을 좋은 페이지 교체 알고리즘으로 평가합니다.

    2-3. 페이지 교체 알고리즘을 제대로 알려면 페이지 폴트 횟수를 알아야 하고 페이지 폴트 횟수는 페이지 참조열을 통해 알 수 있습니다.
        => 중복된 페이지를 참조하는 행위 -> 페이지 폴트 발생 x
        => 2 2 2 3 5 5 5 3 3 7 / 2 3 5 3 7 -> 페이지 참조열이며 5번 발생
    
    2-4. FIFO 페이지 교체 알고리즘
        => 메모리에 가장 먼저 올라온 페이지부터 내쫓는 방식입니다.
        => 프로그램 실행 내내 사용될 내용을 포함하는 페이지가 내쫓기는 일이 생길 수 있습니다.
    
    2-5. 2차 기회 페이지 교체 알고리즘
        => FIFO와 같이 기본적으로 메모리에서 가장 오래 머물렀던 페이지를 대상으로 내보낼 페이지를 선별합니다.
        => 그러나 페이지의 참조 비트가 1일 경우, 참조 비트를 0으로 만든 뒤 현재 시간을 적재 시간으로 설정합니다.
        => 이렇게 오래 머무른 페이지에게 기회를 주는 방식입니다.
    
    2-6. 최적 페이지 교체 알고리즘으로
        => CPU에 의해 참조되는 횟수를 고려하는 페이지 교체 알고리즘입니다.
        => 보조기억장치로 내보내야 할 페이지는 앞으로 사용 빈도 가장 낮은 페이지로 결정하는 것입니다.
        => 타 페이지 교체 알고리즘에 비해 페이지 폴트 발생 빈도가 가장 낮습니다.
        => 다만 실제 구현 어려움 -> 앞으로 오랫동안 사용되지 않은 페이지를 예측하기가 어렵습니다.
    
    2-7. LRU 페이지 교체 알고리즘
        => 가장 오랫동안 사용되지 않은 페이지를 교체하는 알고리즘입니다.
        => 최근에 사용되지 않은 페이지는 앞으로도 사용되지 않을 것이라는 토대로 만들어진 알고리즘입니다.


3. 스래싱
    3-1. 프로세스가 사용할 수 있는 프레임 수가 적어도 페이지 폴트가 자주 발생합니다.
    3-2. 프레임이 부족하면 페이지 폴트가 자주 발생하고 CPU가 페이지 교체에 너무 많은 시간을 들여 성능에 악영향을 초래합니다.
    3-3. 프로세스가 실제 실행되는 시간보다 페이징에 더 많은 시간을 소요하여 성능이 저해되는 문제를 스래싱이라고 합니다.
    3-4. 스래싱이 발생하는 근본적인 원인은 각 프로세스가 필요로 하는 최소한의 프레임 수가 보장되지 않았기 때문입니다.


4. 프레임 할당
    4-1. OS는 각 프로세스들이 무리 없이 실행하기 위한 최소한의 프레임 수를 파악하고 프로세스들에 적절한 수만큼 프레임을 할당해 줄 수 있어야 합니다.
        => 프레임 할당

    4-2. 균등 할당
        => 모든 프로세스에게 균등하게 프레임을 제공하는 방식입니다.
        => 프로세스들의 크기는 각기 다르고 동일하게 프레임을 할당하는 것은 비효율적입니다.

    4-3. 비례 할당
        => 프로세스의 크기에 따라 프레임을 제공하는 방식입니다.
        => 균등 할당과 비례 할당은 프로세스 실행 과정을 고려하지 않고 프로세스의 크기와 물리 메모리의 크기만 고려한 방식이라는 점에서 비례 할당이라고 합니다.
    
    => 실행 후 프로세스가 더 프레임이 필요할 수도 / 프레임이 덜 받아도 되는 경우가 있습니다.

    4-4. 작업 집합 모델
        => 프로세스가 일정 기간 동안 참조한 페이지 집합을 기억하여 빈번한 페이지 교체를 방지합니다.
        => 참조 지역성의 원리에 따라 집합을 기억합니다. 
        => CPU가 특정 시간 동안 주로 참조한 페이지 개수만큼만 프레임을 할당 -> 페이지 교체 빈번 발생 x
        => 실행 중인 프로세스가 일정 시간 동안 참조한 페이지의 집합을 작업 집합이라고 합니다.
    
    4-5. 페이지 폴트 빈도
        => 두 가지 가정에서 생겨난 아이디어 입니다.
            1. 페이지 폴트율이 너무 높으면 해당 프로세스는 너무 적은 프레임을 갖고 있다.
            2. 페이지 폴트율이 너무 낮으면 그 프로세스가 너무 많은 프레임을 갖고 있다.
        => 그림에서 상한선과 하한선을 만들어 놓습니다.
        => 페이지 폴트율이 상한선 보다 높아지면 프레임 더 할당
        => 페이지 폴트율이 하한선 보다 낮아지면 해당 프레임 회수
