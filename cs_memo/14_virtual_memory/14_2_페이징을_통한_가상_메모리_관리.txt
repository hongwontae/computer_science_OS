1. 가상 메모리
    => 실행하고자 하는 프로그램을 일부만 메모리에 적재하여 실제 물리 메모리 크기보다 더 큰 프로세스를 실행할 수 있게 하는 기술입니다.
    => 가상 메모리 관리 기법에는 페이징과 세그멘테이션이 존재합니다.


2. 페이징
    2-1. 페이징이란 -> 메모리의 물리 주소 공간을 프레임으로 자르고 / 프로세스의 논리 주소 공간을 페이지 단위로 자른 뒤 
        각 페이지를 프레임에 할당하는 가상 메모리 기법입니다.
    2-2. 이러한 페이징을 사용하면 외부 단편화는 발생하지 않습니다. -> 작은 메모리 공간을 작은 프레임이 사용할 수 있기 때문입니다.
    2-3. 페이징 시스템에서는 스와핑을 페이지 단위로 실행합니다. -> 이 때는 페이지 아웃, 페이지 인이라고 부릅니다.
    2-4. 한 프로세스를 실행하기 위해서는 프로세스 전체가 메모리에 적재될 필요가 없습니다.
        => 당장 실행에 필요한 일부 페이지만 메모리 적재하고 당장 실행에 필요없는 페이지들은 보조기억장치에 남겨둘 수 있습니다.
        => 이를 통해 메모리보다 더 큰 프로세스를 실행할 수 있습니다.


3. 페이지 테이블
    3-1. 프로세스가 메모리에 불연속적으로 적재 -> CPU 입장에서 순차적으로 처리할 수 없습니다.
        => 프로세스가 메모리에 불연속적으로 배치되면 CPU 입장에서 다음에 실행할 명령어 위치 찾기가 어렵습니다.
    3-2. 페이지 테이블 : 페이지 번호와 프레임 번호를 짝지어 주는 이정표입니다.
        => CPU가 페이지 번호만 보고 해당 페이지가 적재된 프레임을 찾을 수 있게 합니다.
        => 어떤 페이지가 어떤 프레임에 할당되었는지를 알려줍니다.
    3-3. 프로세스마다 각자의 페이지 테이블이 존재합니다.
        => 물리 주소상에서 분산되어 저장되었더라도 CPU 입장에서 바라본 논리 주소는 연속적으로 보일 수 있습니다.


4. 내부 단편화
    4-1. 페이징은 프로세스의 논리 주소 공간을 페이지라는 일정한 크기 단위로 자릅니다.
    4-2. 모든 프로세스가 페이지 크기에 딱 맞게 잘리는 것은 아닙니다.
        => 페이지 크기는 10kb / 프로세스 크기 108kb -> 마지막 페이지는 2kb 낭비됩니다.
        => 이를 내부 단편화라고 합니다.
    4-3. 내부 단편화는 하나의 페이지 크기보다 작은 크기로 발생합니다.
        => 페이지 크기를 작게 설정하면 단편화 크기는 작아질 것으로 예상할 수 있습니다.
        => 그러나 너무 작아지면 페이지 테이블이 커지는 단점이 있습니다.


5. 페이지 테이블 베이스 레지스터 (PTBR)
    5-1. 프로세스마다 각자의 페이지 테이블을 가지고 있고, 각 프로세스의 페이지 테이블들은 메모리에 적재되어 있습니다.
        => 페이지 테이블의 주소는 각 프로세스 PCB에 기록되고 문맥 교환 시 변경됩니다.
    5-2. 그리고 CPU 내의 PTBR은 각 프로세스의 페이지 테이블이 적재된 주소를 가리키고 있습니다.
        => 프로세스 A가 실행될 떄 PTBR은 프로세스 A의 페이지 테이블 주소를 가리키고 CPU는 이를 통해 적재된 프레임을 알 수 있습니다.
    5-3. 페이지 테이블을 메모리에 두면 메모리 접근 시간이 2배로 늘어납니다.
        => 메모리에 있는 페이지 테이블을 보기 위해 한 번, 알게된 프레임에 접근하기 위해 한 번 -> 2번
    5-4. CPU 곁에는 TLB라는 페이지 테이블의 캐시 메모리가 있습니다.
        => TLB는 페이지 테이블의 캐시이기 때문에 페이지 테이블의 일부 내용을 저장합니다.
        => 참조 지역성에 근거해 최근에 사용된 페이지 위주로 가져와 저장합니다.
        => CPU가 발생한 논리 주소에 대한 페이지 번호가 TLB에 존재 -> TLB 히트
        => 페이지 번호가 TLB에 없을 경우 -> 두 번 접근 -> 이를 TLB 미스


6. 페이징에서의 주소 변환
    6-1. 특정 주소에 접근하려면 두 가지 정보가 필요합니다.
        => 어떤 페이지 혹은 프레임에 접근하고 싶은지 / 접근하려는 주소가 그 페이지 혹은 프레임으로부터 얼마나 떨어져 있는지(페이지, 프레임 내에서 거리)
    6-2. 페이징 시스템에서는 모든 논리 주소가 기본적으로 페이지 번호와 변위로 이루어져 있습니다.
        => 페이지 번호 : 접근하고자 하는 페이지 번호 / 변위 : 프레임의 시작 번지로부터 얼만큼 떨어져 있는지 정보


7. 페이지 테이블 엔트리
    7-1. 페이지 테이블의 각각의 행들을 페이지 테이블 엔트리라고 합니다.
    7-2. 페이지 테이블에 담기는 정보는 페이지 번호, 프레임 번호 뿐만 아니라 다양하고 중요한 정보가 있습니다.
    7-3. 유효 비트 : 해당 페이지에 접근 가능한지 여부
        => 프로세스를 이루는 모든 페이지가 메모리에 있지 않습니다. (스와핑)
        => 일부 페이지는 스왑영역에 있을 수 있습니다.
        => 유효 비트는 현재 페이지가 메모리에 적재 or 스왑 영역에 존재를 알려주는 비트입니다.
        => CPU가 유효 비트 0 페이지에 접근 -> 페이지 폴트(page falut)가 발생합니다.
    7-4. 페이지 폴트 처리 과정
        1. CPU는 기존의 작업 내역 백업
        2. 페이지 폴트 처리 루틴 실행
        3. 페이지 처리 루틴은 원하는 페이지를 가져온 뒤 유효 비트를 1로 변경
        4. 페이지 폴트 처리했다면 CPU 해당 페이지 접근 가능
    7-5. 보호 비트
        => 보호 비트를 통해 read, write, excute를 나타낼 수 있습니다.
        => 보호 비트가 활성화되지 않은 rwx를 하면 OS가 이를 막습니다.
    7-6. 참조 비트
        => CPU가 해당 페이지에 접근한 적이 있는지를 나타냅니다.
        => 적재 이후 CPU가 읽거나 쓴 페이지는 1 / 적재 이후 한 번도 읽거나 쓴 적이 없는 페이지 0
    7-7. 수정 비트 (더티 비트)
        => 해당 페이지에 데이터를 쓴 적이 있는지 없는지 수정 여부를 알려주는 비트입니다.
        => 1이면 변경된 적 있음 / 0이면 변경된 적 없음
        => 수정 비트는 페이지가 메모리에서 사라질 때 보조기억장치에 쓰기 작업을 해야 하는지, 할 필요가 없는지를 판단하기 위해서 존재
        => CPU가 쓰기 작업을 수행한 페이지의 경우 보조기억장치에 저장된 페이지의 내용과 메모리에 저장된 페이지의 내용은 서로 다릅니다.
        => 즉, ram에 적재된 페이지와 보조기억장치에 저장된 페이지가 서로 존재합니다. -> 수정 비트가 0이면 같은 내용
        => 근데 CPU가 쓰기 작업을 하면 보조기억장치에 쓰는게 아니라 ram의 페이지에 씀
        => 쓰기 작업 페이지가 나갈 떄 보조기억장치에 기록하는 작업이 필요 -> 이 여부를 확인하려고
