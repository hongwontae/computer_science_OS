1. 쓰기 시 복사
    1-1. 부모 프로세스에서 fork 시스템 호출을 통해 자식 프로세스를 생성
        => 자식은 다른 메모리 영역을 가지고, 자신만의 페이지 테이블...
        => 프로세스 생성 시간을 늦추고 불필요한 메모리 낭비를 야기합니다.
        
    1-2. 쓰기 시 복사에서는 부모 프로세스와 동일한 자식 프로레스가 생성되면 자식 프로세스로 하여금 부모 프로세스와 동일한 프레임을 가리킵니다.
        => 부모 프로세스의 메모리 공간을 복사하지 않고도 동일한 코드 및 데이터 영역을 가리킬 수 있습니다.
    
    1-3. 부모 프로세스 혹은 자식 프로세스 둘 중 하나가 페이지에 쓰기 작업을 하면 그 순간 해당 페이지가 별도의 공간으로 복제됩니다.
        => 각 프로세스는 자신의 고유한 페이지가 할당된 프레임을 가리킵니다.
        => 프로세스 생성 시간을 줄이고 메모리 공간 절약도 가능합니다.
    

2. 계층적 페이징
    2-1. 프로세스를 이루는 모든 페이지 테이블 엔트리를 메모리에 두는 것은 큰 메모리 낭비입니다.

    2-2. 페이지 테이블 엔트리를 항상 메모리에 유지하지 않을 수 있는 방법을 계층적 페이징이라고 합니다.

    2-3. 계층적 페이징 (다단계 페이지 테이블)
        => 페이지 테이블을 페이징하여 여러 단계의 페이지를 두는 방법입니다.
        => 프로세스의 페이지 테이블을 여러 개의 페이지로 자르고, 바깥쪽에 페이지 테이블을 하나 더 두어 잘린 페이지 테이블의 페이지들을 가리키게 하는 방법입니다.
        => 즉, 바깥쪽 페이지 테이블은 여러 개로 잘른 페이지 테이블의 정보가 존재합니다. 그리고 outer 페이지 테이블은 항상 메모리에 유지해야 합니다.
        => 계층적 페이징의 논리 주소는 outer_page_number, inner_page_number, offset으로 이루어져 있습니다.
        => outer_page_number를 통해 페이지 테이블 찾고 inner_page_number로 실제 찾을 페이지를 찾고 프레임을 찾고 변위를 더해서 물리 주소를 얻습니다.
        => 이러한 계층적 페이징은 새 개, 네 개.. 이상의 계층으로 구성될 수 있습니다.
