1. 뮤텍스 락
    => 뮤텍스 락은 접근해서는 안 되는 자원에 동시에 접근하지 않도록 만드는 도구입니다.
    => 뮤텍스 락은 하나의 공유 자원에 접근하는 프로세스를 상정한 방식입니다.
    => 임계 구역에 진입한 프로세스는 뮤텍스 락을 통해 임계 구역 접근을 막고 다른 프로세스는 임계 구역이 막혀있다면 기다립니다.
        그리고 뮤텍스 락이 풀리면 임계 구역에 접근할 수 있는 흐름입니다.
    => 프로세스가 임계 구역에 접근할 수 있는지 지속적으로 확인하는 대기 방식을 바쁜 대기라고 합니다.


2. 세마포
    => 여러 공유 자원에 접근하는 프로세스를 상정한 방식입니다.
    => 여러 공유 자원에 여러 프로세스가 접근하고 뮤텍스 락과 동일한 흐름을 갖습니다.
        즉, 세 대의 프린터가 존재하고 4개의 프린터 이용 프로세스가 존재할 떄 3개는 접근하고 1는 대기합니다.
        이 떄 대기는 바쁜 대기입니다.
    => 사용 가능한 공유 자원을 나타내는 전역 변수 S / 임계 구역에 들어가도 좋은지, 기다려야 할지 알려주는 wait 함수
        임계 구역 앞에서 기다리는 프로세스에 가도 된다는 신호를 주는 signal 함수
    => 임계 구역 진입 전후로 wait()과 signal()를 호출합니다.
    => wait를 통해 전역 변수를 지속적으로 확인하고 전역 변수가 0이 아닌 양수라면 S-1를 하고 signal()를 호출하면서 들어갑니다.
    => Singal()에 진입하면 임계 구역의 작업 + 전역 변수를 1 증가시킵니다.
    => 지속적으로 wait으로 확인하는 것보다 전역 변수가 S = 0일 떄 PCB를 대기 큐에 넣는 방식도 있습니다.

    => 세마포 방식은 실행 순서도 제어 할 수 있습니다. 
        -> 전역 변수 0, 먼저 실행할 프로세스 signal, 뒤에 실행할 프로세스 wait


3. 모니터
    => 프로세스가 공유 자원을 접근할 떄 반드시 인터페이스르 통해 접근하는 방식입니다.
    => 모니터를 통해 공유 자원에 접근하고자 하는 프로세스를 큐에 삽입, 큐에 삽인된 순서대로 공유 자원 사용하게 합니다.
    => 공유 자원 연산(인터페이스)에는 하나의 프로세스만 들어올 수 있습니다
    
    => 실행 순서 제어를 위한 동기화는 조건 변수를 사용합니다.
    => 조건 변수 프로세스나 스레드의 실행 순서를 제어하기 위해 사용
    => 조건 변수로 wait과 signal 연산을 수행할 수 있습니다.
    => wait : 호출한 프로세스의 상태를 대기 상태로 전환하고 일시적으로 조건 변수에 대한 대기 큐에 삽입하는 연산
        -> 모니터에 진입하기 위해 삽입되는 큐 != wait이 호출되어 실행이 중단된 프로세스들이 삽입되는 큐
    => wait은 모니터에 이미 진입한 프로세스의 실행 조건이 만족될 때까지 잠시 실행이 중단되어 기다리기 위해 만들어진 큐
    => x.wait()를 호출하면 모니터 큐에서 빠져나와 조건 변수 x 큐에 들어갑니다. -> 다른 프로세스 진입가능
    => 다른 프로세스의 signal() 연산을 통해 x.wait 큐에서 나와 모니터 큐로 갈 수 있습니다.
    => 이렇게 실행 순서를 제어할 수 있습니다.
