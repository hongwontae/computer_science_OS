1. 프로세스 동기화
    => 프로세스들 사이의 수행 시기를 맞추는 것을 의미합니다.
    => 크게 두 가지가 존재합니다.
    => 실행 순서 제어 : 프로세스를 올바른 순서대로 실행하기
    => 상호 배제 : 동시에 접근해서는 안 되는 자원에 하나의 프로세스만 접근하게 하기
    => 프로세스 뿐만 아니라 스레드도 동기화 대상입니다. 실행의 흐름을 갖는 모든 것은 동기화 대상입니다.


2. 실행 순서 제어를 위한 동기화
    => Reader 프로세스와 Write 프로세스가 존재하고 둘 다 Book.txt에 접근한다고 가정
    => Reader 프로세스는 Book.txt 안에 값이 존재한다는 특정 조건이 만족되어야만 실행을 이어나갈 수 있습니다.
    => 이렇게 동시에 실행되는 프로세스를 올바른 순서대로 실행하는 것이 실행 순서 제어를 위한 동기화입니다.


3. 상호 배제를 위한 동기화
    => 상호 배제는 공유가 불가능한 자원의 동시 사용을 피하기 위해 사용되는 알고리즘입니다.
    => 프로세스 a는 저축된 금액에 2만원을 넣는 프로세스 / 프로세스 b는 저축된 금액에 5만원을 넣는 프로세스
    => 상호 배제 동기화가 제대로 이루어지지 않으면 이상한 결고값이 나올 수 있습니다.
    => 상호 배제를 위한 동기화_1 사진을 보면 읽어 들인 후 값을 더하고 저장하지 않고 문맥 교환이 일어났습니다.
    => 그렇다면 12만원, 15만원.. 이렇게 의도치 않은 금액이 나올 수 있습니다.
    => 상호 배제를 위한 동기화_2 사진을 보면 문맥교환이 일어났다고 하더라도 프로세스 b는 접근할 수 없습니다.
    => a의 작업 완료되야 b의 프로세스가 접근하여 처리할 수 있습니다.


4. 생산자와 소비자 문제
    => 생산자는 물건을 계속해서 생산하는 프로세스
    => 소비자는 생산자와 물건을 계속해서 소비하는 프로세스
    => 생산자와 소비자는 총합이라는 데이터를 공유하고 있습니다.
    => 생산자와 소비자가 동시에 실행될 떄 생산자 프로세스나 소비자 프로세스가 정해진 흐름을 완료하지 않았는데
        동시에 접근하지 말아야 하는 자원에 접근해 올바르지 않은 총합이 나올 수 있습니다.


5. 공유 자원과 임계 구역
    => 동시에 실행되는 프로세스들이 접근하는 자원을 공유 자원이라고 합니다.
    => 동시에 실행하면 문제가 발생하는 자원에 접근하는 코드 영역을 임계 구역이라고 합니다.
    => 두 개 이상의 프로세스가 임계 구역에 진입하고자 하면 둘 중 하나는 대기해야 합니다.
    => 임계 구역에 먼저 진입한 프로세스의 작업이 마무리되면 기다렸던 프로세스가 임계 구역에 접근합니다.
    => 레이스 컨디션 : 잘못된 실행으로 인해 여러 프로세스가 동시 다발적으로 임계 구역의 코드를 실행하여 문제가 발생하는 경우를 의미합니다.
    => 상호 배제를 위한 동기화를 통해 임계 구역에 두 개 이상의 프로세스가 동시에 접근하지 못하도록 관리합니다.


6. 상호 배제를 위한 동기화 원칙
    6-1. 상호 배제 : 한 프로세스가 임계 구역에 진입했다면 다른 프로세스는 임계 구역에 들어올 수 없다.
    6-2. 진행 : 임계 구역에 어떤 프로세스도 진입하지 않았다면 임계 구역에 진입하고자 하는 프로세스는 들어갈 수 있어야 한다.
    6-3. 유한 대기 : 한 프로세스가 임계 구역에 진입하고 싶다면 그 프로세스는 언젠가는 임계 구역에 들어올 수 있어야 한다. (무한정 대기 x)
